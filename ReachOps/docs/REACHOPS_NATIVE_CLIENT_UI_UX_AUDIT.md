# ReachOps 原生客户端启动页 UI/UX 审计

日期：2026-07-04

## 审计范围

- 原生 Mac 客户端启动后的运营控制台。
- 主标签页：获客任务、线索分析、触达执行、账号诊断、报告中心。
- 依据：用户截图、`ReachOps/workbench/console.py`、`ReachOps/workbench/standalone_app.py`。

## 当前问题

1. 启动页只显示顶部导航，主体区域空白。
   - 影响：运营无法判断是加载中、无数据、环境失败，还是页面坏了。
   - 优先级：P0。

2. 首屏缺少页面标题和当前状态。
   - 影响：切换标签后缺少上下文，用户不知道当前页要完成什么任务。
   - 优先级：P1。

3. 空表格没有空态说明。
   - 影响：新用户会把“暂无数据”误判为 UI 没加载。
   - 优先级：P1。

4. 启动脚本之前只检查 `import tkinter`。
   - 影响：`import tkinter` 成功但 `tk.Tk()` 失败时，会出现启动失败但日志为空。
   - 优先级：P0。

## 优化原则

- 视觉语言采用灰色专业工具台：深灰背景、灰色内容面板、清晰边框、白色正文和浅灰辅助文字。
- 日志区域采用终端语义配色：黑底、浅灰正文，计划/检查为蓝色，成功为绿色，警告为黄色，错误为红色。
- 首屏必须可操作：推广目标、账号分组、刷新分组、开始获客、日志入口必须清晰。
- 标签页必须有明确边界：每个主标签页都有标题、说明和内容容器。
- 空态必须解释下一步：没有数据时告诉运营应该开始获客、刷新分组或查看诊断。
- 环境失败必须可理解：原生 Tk 不可用时，明确显示阻断原因，并引导使用 Web 运营面板。

## 已完成优化

1. 页面内容栈改为显式 `tk.Frame`。
   - 避免 macOS ttk/Aqua 深色主题导致主体区域不可见。

2. 新增固定页面头部。
   - 显示当前页标题、页面说明、运行状态徽标。
   - 切换主标签页时同步更新标题和说明。

3. 新增表格空态提示。
   - 空数据页面显示“暂无数据；开始获客或刷新工作台后会在这里显示结果。”

4. 统一高对比控制台样式。
   - 主体、导航、边框、文案、状态徽标使用统一设计令牌。
   - 业务界面保持灰色主色和白色文字，避免浅灰背景配深灰文字造成相似度过高。
   - 执行终端使用黑底终端配色，按 INFO / SUCCESS / WARN / ERROR 自动区分日志。

5. 保留完整 5 个主标签页。
   - 原生客户端继续使用完整 `GrowthOpsConsole`，不降级为单页轻量控制台。

6. 启动脚本改为真实 Tk 探测。
   - 必须成功创建 `tk.Tk()` 才会启动客户端。
   - 当前本机 Tk 不可用时，输出明确检测日志。

## 验收标准

- 原生 UI 代码必须使用完整 `GrowthOpsConsole`。
- 5 个主标签页必须存在并可切换。
- 主体内容区域不能依赖空白 ttk 容器。
- 每个页面必须有标题/说明或可见内容。
- 空数据状态必须有下一步提示。
- 业务界面必须有足够对比度，主文字使用白色，辅助说明使用浅灰，控件和边框必须从灰色背景中清晰分离。
- 日志必须符合终端显示习惯，错误、警告、成功、执行阶段应有明确语义色。
- 客户端不能回退到旧版低对比色或未定义颜色变量。
- 原生启动脚本不能把 `import tkinter` 成功误判为可启动。

## 当前限制

当前 Mac 上没有可用 Python/Tk 图形运行时：

- `/usr/bin/python3` 和 `python3` 创建 `tk.Tk()` 时直接中止。
- `.venv/bin/python` 创建 `tk.Tk()` 时报 `tk.tcl` / `NaN` 错误。
- Homebrew Python 缺少 `_tkinter`。

因此本轮无法在本机完成真实 Tk 截图复测。当前通过代码结构合同、编译、审计脚本和启动脚本真实 Tk 探测保证交付边界。
